# Complete requirements traceability

This register preserves every bullet and prose block from the attached continuation, including the final execution instructions. Source: `complete-requirements-source.txt`. Earlier product direction and private-owner requirements remain in force. Rows may contain closely related clauses from one source paragraph; all clauses must pass before the row can become verified.

Status is deliberately conservative: **in progress** can include implemented and tested subparts while the whole row remains incomplete. **Blocked** does not authorize invented results. No phase beyond P1 may be presented as completing the missing live milestone.

Phases: P0 reconciliation; P1 persistent chat and durable research; P2 production hosting/portability; P3 voice/memory; P4 approvals and isolated tools; P5 specialists/proactivity/artifacts; P6 training/data; P7 council/mobile/physical devices. P6 preparation may proceed while P1 credentials are unavailable. Paid collection/training and public deployment require a specific approved estimate/action.

Each acceptance check below requires observable evidence, including negative/ownership tests where relevant. A prose description alone is not acceptance evidence. File references are relative to the app root unless otherwise stated.
