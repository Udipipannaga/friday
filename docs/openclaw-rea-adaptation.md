# OpenClaw study and FRIDAY adaptation — 2026-10-14

The owner asked to use [REA](https://github.com/morluto/rea) to inspect [OpenClaw](https://github.com/openclaw/openclaw), then adapt useful behavior into FRIDAY. OpenClaw publishes source under MIT, so no binary decompilation was needed. We studied commit `68c3f3fb660c5dd808231199b0fe265ea26086f2` in a sparse, read-only checkout. No OpenClaw or REA code was copied into FRIDAY.

REA's static JavaScript application analyzer ran inside a temporary container with only six OpenClaw cron files mounted read-only. The analysis Evidence ID is `ev_7d309e6f9cb2462483b22d28713badb477cfc3f3859266e214970e72176184ea`. A module trace from `src/cron/service/jobs-scheduling.ts` produced Evidence ID `ev_5a1f42d8ea0745c4ef620988e56162a01de697f36ff8d172d9f3df2fe6d6ff96`. The source slice covered scheduling, validation, trigger, runner and receipt files; REA parsed all six but marked graph coverage **partial**. Its trace reports static relationships, not runtime execution or a complete OpenClaw architecture. The full raw evidence stays in the local, untracked `work/` directory.

The inspected OpenClaw code separates schedule validation/next-run calculation, execution, and run receipts. OpenClaw's own [automation documentation](https://github.com/openclaw/openclaw/blob/main/docs/cli/cron.md) describes scheduled background jobs. FRIDAY now adapts only the narrow behavior it needs: the owner can enable a seven-day `weekly_note` schedule on a company desk; Celery Beat checks due schedules; the worker reads the company record, saves one private draft with a unique occurrence key, and advances `next_run`. The action is gated by the configured-model setting and has no send, pay, delete, shell, or price-change path. Disabling stops future drafts.

The owner-facing feature is in `frontend/src/OperatingDesk.tsx`; enforcement is in `backend/friday/api.py`, `operating.py`, `tasks.py`, the `006` migration and the `OperatingSchedule` table. Automated tests cover owner-only enablement, strict input, the configured-model gate, one saved draft, repeat-run deduplication and disabling. The deployed image passed an isolated SQLite run with one draft and zero duplicates; the production database migrated to `006` and the HTTPS health endpoint returned 200. The schedule is **off by default** on all desks. A real owner-enabled week-long run, service-failure recovery, and any broader OpenClaw-like tools remain untested or planned.
